# 安全设计

## 当前权限模型

Local Dev MCP 只暴露查询工具。System MCP 额外提供签名清理计划申请（仅写入隔离的审批元数据）与状态查询；不提供目标文件修改。Codex 通过 `enabled_tools` 显式限制可调用工具。

| 能力 | 当前权限 | 说明 |
|---|---|---|
| 项目与 Git 查询 | L0 只读 | 不修改索引或工作区 |
| Runner 状态与日志 | L0 只读 | 固定进程名、固定日志文件、限量脱敏 |
| 系统信息、磁盘、进程 | L0 只读 | 不返回命令行参数和环境变量 |
| 文件名搜索、目录浏览 | L0 只读 | 仅限配置登记的 rootId |
| 文件元数据与文本读取 | L0 只读 | 相对路径、拒绝敏感文件、限量脱敏 |
| 清理候选计划 | L0 只读 | 只估算常见缓存/构建目录，不执行删除 |
| 清理审批计划申请 | L1 仅元数据 | 保存带签名的待审批计划，不批准、不删除 |
| 文件写入、移动、删除 | 不提供 | 后续需要人工审批 |
| Git checkout、commit、push、reset | 不提供 | 后续单独设计 |
| Runner 启动、停止、重启 | 不提供 | 后续需验证官方本地接口 |
| 任意 PowerShell / Shell | 不提供 | 禁止通用命令执行工具 |

## 交付脱敏要求

- 不提交真实 `config/*.yaml`、用户级 Codex 配置、`.local/` 审批密钥、`.env`、日志、数据库文件、私钥或证书。
- 示例配置只能使用占位目录、示例项目和本机回环地址；不得包含个人用户名、真实工作区路径、Runner 绑定标识或可复用凭据。
- 交付前必须运行 `npm run security:scan`；扫描失败时禁止打包、提交或推送。- 扫描同时覆盖工作区交付候选文件与 Git 暂存区对象，避免只扫描工作树而漏掉已暂存的旧内容；被忽略的本机文件若被强制加入暂存区，也会被检查。

- 安全扫描只输出文件位置和风险类别，不输出疑似凭据的内容。

## System MCP 文件边界

- 只允许访问本机 `config/system-mcp.yaml` 中显式登记的根目录；真实目录路径仅保存在本机被 Git 忽略的配置文件中，仓库示例只使用占位路径。
- MCP 输入使用 `rootId + relativePath`，拒绝绝对路径、盘符、ADS 路径、`..` 路径穿越。
- 根目录必须是实际目录且不能是符号链接；访问过程逐级拒绝符号链接，并再次检查 realpath 是否仍位于根目录内。
- 拒绝常见凭证目录和文件：`.ssh`、`.aws`、`.kube`、`.env*`、`.envrc`、`.netrc`、`.git-credentials`、`.npmrc`、SSH 私钥和常见证书/密钥扩展名。
- `search_files` 默认跳过 `.git`、`node_modules`、`dist`、`build`、`target`、`.gradle`、`.idea` 等常见生成目录。
- 大文件扫描、目录分析和 `plan_cleanup` 有最大深度与最大条目数；响应明确标记截断，不把不完整扫描伪装成完整结果。
- `plan_cleanup` 只返回候选路径、估算字节数和文件数，固定标记 `deletionPerformed=false`、`manualReviewRequired=true`。
- `read_text_file` 仅允许常见文本扩展名，默认最多读取 64 KiB，绝对上限 128 KiB；使用有界文件句柄读取，不读取二进制文件。
- 文本读取对常见 JSON/YAML/INI 凭证键、Bearer Token、GitHub Token 和 PEM 私钥块做脱敏。脱敏属于启发式保护，不保证识别所有秘密，因此仍必须限制根目录和敏感路径。
- 进程清单只返回进程名、PID、会话和内存占用，不返回命令行参数或进程环境变量。

## 原生进程调用

- 只调用固定可执行文件，例如 `git`、`tasklist.exe` 和系统 PowerShell。
- 参数使用 argv 数组；不使用 `shell: true`。
- PowerShell 查询脚本是源码内固定常量，不接受模型输入拼接。
- 设置超时和最大输出。
- 不允许模型提供任意可执行文件路径、工作目录或脚本内容。

## 后续写操作审批

第三阶段已实现审批 Core 的计划、签名和一次性票据，但没有真实执行器；未来目标文件写操作必须采用两阶段设计：

1. MCP Tool 只生成操作计划和待审批 ID，不执行写操作。
2. 用户通过独立本地 CLI 查看完整目标、参数、差异、影响范围和预计释放空间。
3. 用户确认后，CLI 生成一次性审批票据，绑定操作类型、目标、参数摘要、资源版本和过期时间。
4. 执行端只接受有效、未使用且与计划完全匹配的票据。
5. 审批 CLI 不作为 MCP Tool 暴露，避免 Agent 自己批准自己的操作。
6. 已实现计划签名、一次性票据核销、过期校验和链式审计；尚未实现真实执行结果记录、独立操作员身份认证或权限隔离。具体限制见 [审批 Core](approval-core.md)。

## 明确禁止

- 不暴露 `execute_command(command)`、任意 shell、任意路径读取或任意文件写入。
- 不自动删除缓存、日志、图片、压缩包或回收站内容。
- 不因模型声称“用户已经确认”就跳过独立审批。
- 不读取密码库、浏览器 Cookie、SSH 私钥、云凭证或环境变量文件。
